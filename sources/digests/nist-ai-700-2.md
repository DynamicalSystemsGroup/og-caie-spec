# NIST AI 700-2, ARIA 0.1 Pilot Evaluation Report — digest

Source: `src:nist-ai-700-2`, committed at `sources/archive/NIST.AI.700-2.pdf`
(public domain). Report page numbers; PDF page = report page + 7.

- **Application** (App. A, p. 16): "A generative artificial intelligence-based system to which NIST is given API access to test. The object of ARIA evaluations."
- **Field testing** (p. 16): "Testing level which evaluates what happens when human testers interact with applications in realistic settings (i.e., use that might occur in the real world)."
- **Guardrail** (p. 17): "An application requirement specifying both 1) permitted information that can be shared with a user, and 2) prohibited information that should be withheld from a user."
- **Model testing** (p. 17): "Testing level which evaluates capabilities of an AI application with a pre-defined set of prompts."
- **Red teaming** (p. 17): "Testing level which evaluates whether applications adhere to guardrails in response to adversarial prompting or stress testing by human testers."
- **Scenario** (p. 17): "The context in which structured AI evaluation activities are performed."
- **Tester** (p. 17): "Individual who interacts with an application within the ARIA test environment."
- **Validity** (p. 18): "Validation: confirmation, through the provision of objective evidence, that the requirements for a specific intended use or application have been fulfilled [7]."
- **Annotation outcomes** (§3.1, p. 5): "Yes" (a guardrail violation occurred), "No", "Unable to Determine", "N/A", which map onto EARL failed, passed, cantTell, inapplicable (the "Yes" answers the violation question, so it is the failed outcome; corrected on sheet 10).
